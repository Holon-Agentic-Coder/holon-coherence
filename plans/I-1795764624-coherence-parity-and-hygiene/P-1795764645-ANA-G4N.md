## Step 2: Close all `sqlite3.connect` handles with `contextlib.closing` in `openbrain_memory.py`

### Step Intent & Git Integration

- **Sub-intent recommendation:** none (inline step)
- **Reasoning:** In Python's `sqlite3`, using a connection as a context manager (`with sqlite3.connect(...) as conn:`)
  only commits or rolls back transactions; it does not call `conn.close()`. Wrapping with `contextlib.closing` fixes the
  resource leak cleanly.
- **Step type:** implementation
- **Exploration level:** none
- **Git branch:** same worktree feature branch

### Implementation Details

1. In `src/holon_coherence/openbrain_memory.py` (currently 111 lines; budget cap 200 lines):
   - Add `import contextlib` in sorted stdlib import order (above `import json`).
   - Update all three `sqlite3.connect(self.db_path)` sites:
     - `_init_db` (line 21): `with contextlib.closing(sqlite3.connect(self.db_path)) as conn:` (retaining
       `conn.commit()`).
     - `store_memory` (line 48): `with contextlib.closing(sqlite3.connect(self.db_path)) as conn:` (retaining
       `conn.commit()` and `return cursor.lastrowid or 0` inside the `with` block so `conn.close()` executes cleanly on
       return or exception).
     - `fetch_memories` (line 81): `with contextlib.closing(sqlite3.connect(self.db_path)) as conn:`.
   - Confirm no other `sqlite3.connect` calls exist in `openbrain_memory.py`.
   - Ensure zero docstrings and zero comments are added, and total line count stays `<= 200`.
