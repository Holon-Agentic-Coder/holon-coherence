## Step 2: Create `scripts/check_no_harness_references.py`

### Step Intent & Git Integration

- **Sub-intent recommendation:** none (inline step)
- **Reasoning:** Implements the two operational modes (`diff` for PR CI enforcement and `tree` for repository-wide clean-up discovery) with fail-closed semantics.
- **Step type:** implementation
- **Exploration level:** none
- **Git branch:** same feature branch.

### Implementation Details

- Start line 1 with `#!/usr/bin/env python3` and `from __future__ import annotations`.
- Import `Finding`, `scan_line`, and `scan_text` from `scripts.harness_reference_patterns` with a fallback `from harness_reference_patterns import ...` (mirroring `scripts/pre_commit_check.py`) so the script works whether invoked as `python3 scripts/check_no_harness_references.py` or imported as `scripts.check_no_harness_references`.
- Build an `argparse` CLI with two subcommands:
  - `diff`: accepts `--base <ref>` (required), `--head <ref>` (required), `--repo <path>` (default `.`), and optional PR body inputs (`--pr-body <text>`, `--pr-body-file <path>`, `--pr-body-env <var>`).
    - Runs `git -C <repo> diff --unified=0 --no-color <base>...<head>` (falling back only if explicitly desired, or using `<base>..<head>` when base/head are SHAs; note `git diff --unified=0 --no-color <base> <head>` works reliably on two commit SHAs even across detached checkouts and shallow/merge-base edges — document clearly and fail closed if `returncode != 0` or `OSError` occurs).
    - Fails closed: if `git` fails, raises `OSError`, returns non-zero, or `--pr-body-file` cannot be read, print a clear error to `sys.stderr` and return exit code `2`.
    - Parses unified diff output: tracks current file from `+++ b/<path>` (ignoring `/dev/null`), tracks new-file line number from `@@ -<old> +<new_start>[,<new_count>] @@`, and scans only added lines (lines starting with `+` and not `+++ `), incrementing the line counter for each added line. Removed (`-`) lines are skipped so clean-up PRs are not blocked.
    - Scans the PR body text (when non-empty) via `scan_text(pr_body, "PR_BODY")`.
    - Prints each finding as `<source>:<line_number>: [<pattern_name>] <match_text>` to `sys.stderr` (or `sys.stdout`) and returns `1` if findings exist, `0` otherwise.
  - `tree`: accepts `--root <path>` (default `.`).
    - Discovers candidate files under `--root`: if `--root` is a git worktree (`git -C <root> rev-parse --is-inside-work-tree` succeeds), uses `git -C <root> ls-files -z`; otherwise walks the directory with `os.walk` skipping `.git`, `.venv`, `__pycache__`, `.pytest_cache`, `.ruff_cache`, `node_modules`.
    - Skips binary files (files containing `b"\0"`).
    - Scans every text file line by line with `scan_text` and prints `<rel_path>:<line_number>: [<pattern_name>] <match_text>` for every hit.
    - Returns `1` if any matches are found, `0` if clean, `2` if `--root` does not exist or cannot be scanned.
- Keep functions small and single-purpose to satisfy Ruff (`max-complexity <= 10`, `max-args <= 5`, `max-branches <= 12`, `max-returns <= 6`, `max-statements <= 50`) and keep the file <= 200 lines with zero docstrings and zero comments.
